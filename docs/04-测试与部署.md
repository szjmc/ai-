内容修改测试会真实写对象和台账，因此用 `KB_STORAGE_ROOT` 指向临时目录，**不污染你自己的文件列表**：

```ts
// tests/content-edit.test.ts
const sandbox = mkdtempSync(path.join(tmpdir(), "kb-content-"));
process.env.KB_STORAGE_ROOT = sandbox;          // 存储路径惰性解析，设在这里即可生效

import { saveUploadedFile, readKnowledgeObject, updateKnowledgeFileContent } from "../src/lib/knowledge";

after(async () => {
  delete process.env.KB_STORAGE_ROOT;
  await rm(sandbox, { recursive: true, force: true });
});
```

内容修改测试直接验证字节落盘，不只看接口返回：

```ts
// tests/content-edit.test.ts
test("text file content can be edited and saved as a new version", async () => {
  const initial = await saveUploadedFile({
    originalName: "修改测试.md",
    bytes: Buffer.from("# 初始正文\n\n这是第一版内容。"),
    collectionName: "测试集合", storedName: "修改测试_init01.md", createdBy: 1,
  });
  assert.equal(initial.version_no, 1);

  const updated = await updateKnowledgeFileContent(initial.id, {
    bytes: Buffer.from("# 修改后的正文\n\n这是第二版内容，已在线修改！"),
    updatedBy: 2,
  });
  assert.equal(updated.version_no, 2);
  assert.equal(updated.updated_by, 2);

  // 回读对象，确认真的写进去了
  const { bytes } = await readKnowledgeObject(initial.id);
  const text = bytes.toString("utf8");
  assert.match(text, /修改后的正文/);
  assert.doesNotMatch(text, /第一版内容/);
});
```

DOCX 大图测试用真实可用的 PNG（随机像素，不可压缩），确保夹具超过旧的 1.5MB 内联上限：

**自带数据、用完清理**：测试不依赖任何预置样本，自己上传夹具，`finally` 里删除。

```js

try {
  const fixture = await context.request.post('/api/v1/file/uploadFile', { multipart: { … } });
  createdIds.push((await fixture.json()).data.id);
  // …断言…

```

操作人目录按设计**没有删除接口**，所以相关测试先快照文件、结束时还原：

```js
const operatorsFile = process.env.KB_OPERATORS_FILE || 'storage/operators.json';
const operatorsBefore = await readFile(operatorsFile, 'utf8').catch(() => null);
try { /* …新增、改名、断言… */ } finally {
```

## 6. 部署

### 前置条件

1. **MySQL** 可达，且目标库已建 `knowledge_files` 表：
   ```bash
   mysql -uroot -p123456 test_db < backend/sql/knowledge_files.sql
   ```
   > 已有表不要重复执行。系统只做 `SELECT … LIMIT 0` 验证，不会自动建表或改表。

2. **MinIO** 可达，桶会在首次上传时自动创建（`ensureMinioBucket`）。

3. **配置写在 `.env.local`**（优先级高于 `.env`，不会被平台构建覆盖）。

### 启动

```bash
npm install
npm run build
npm run start      # 默认 3000 端口
```

### 验证部署

```bash
curl http://127.0.0.1:3000/api/health
# 正常应为：{"ok":true,"database":true,"minio":true,"mode":"mysql",…}

curl http://127.0.0.1:3000/api/diagnostics   # 看详细连通性，不含密码
```

| `health` 字段 | 含义 |
| --- | --- |
| `database: true` | MySQL 已连通且 `knowledge_files` 表存在 |
| `minio: true` | MinIO 已连通且桶可用 |
| `mode: "mysql"` | 正在使用真实数据库；`"local"` 表示降级到本地暂存 |

### ⚠️ 关于 `127.0.0.1`

配置里的 `127.0.0.1` 指的是**运行这个 Next.js 进程的机器**。

- 在你自己的电脑上运行 → 连的是你电脑上的 MySQL/MinIO ✅
- 在云端/容器里运行 → 连的是云端/容器自身，**看不到你电脑上的数据**

容器部署时要把 `MYSQL_HOST` / `MINIO_ENDPOINT` 改成容器可访问的主机地址。

### 文件上限

单文件 50MB。`next.config.ts` 已放开 Next.js 的 body 限制：

```ts
const nextConfig: NextConfig = {
  experimental: {
    proxyClientMaxBodySize: "60mb",   // 不设会在 10MB 处静默截断二进制
    serverActions: { bodySizeLimit: "60mb" },
  },
};
```

## 7. 与 FastAPI 后端的关系

`backend/` 下是你提供的 Python 代码，**业务逻辑一行未改**，只补了各层空的 `__init__.py`、`requirements.txt` 和 `sql/knowledge_files.sql`。

```
backend/
├── main.py                                  # FastAPI 入口，挂载 /api/v1/file
├── .env                                     # MinIO + MySQL 配置
├── sql/knowledge_files.sql                  # 建表脚本
├── requirements.txt
└── app/
    ├── config.py                            # Settings
    ├── routers/{base_router,file_handle_router}.py
    ├── services/knowledge_file_service.py
    ├── dao/knowledge_file_dao.py
    ├── models/mysql/knowledge_file.py       # SQLAlchemy 模型
    ├── schemas/{common,knowledge_file}.py
    ├── exceptions/base_api_exception.py
    └── utils/{file_handler,minio_client}.py
```

### 协作方式

两者**共用同一张 MySQL 表和同一个 MinIO 桶**：

```
         ┌─ FastAPI (8018) ──┐
上传请求 ─┤                   ├─► MySQL knowledge_files + MinIO knowledge-base
         └─ Next.js (3000) ──┘
```

Next.js 上传时会先探活 FastAPI（1.5 秒超时）：

| 情况 | 行为 |
| --- | --- |
| FastAPI 在线 + 文档类型 | 转发给 FastAPI 处理，保持你原有的入库逻辑 |
| **分片请求（任何情况）** | **始终转发 FastAPI，Next.js 不做本地实现** |
| FastAPI 离线 | Next.js 自己写 MinIO + MySQL，结果完全一致 |
| 图片类型 | 始终走 Next.js（原 Python 白名单不含图片，不改你的代码） |

### 分片功能必须启动 FastAPI

上传可以不依赖 FastAPI（Next.js 有等价实现），但**分片是纯透传，没有本地兜底**。
FastAPI 未启动时，分片窗口会显示"解析服务未连接"并禁用提交按钮。

分片还需要这三个外部服务同时就绪：

| 依赖 | 用途 | 配置项 |
| --- | --- | --- |
| MinIO | 下载原文件 | `MINIO_ENDPOINT` |
| Ollama | 生成向量 | `OLLAMA_BASE_URL`、`EMBEDDING_MODEL` |
| Milvus | 存储分片向量 | `MILVUS_HOST`、`MILVUS_PORT`、`MILVUS_DEFAULT_COLLECTION` |

> ⚠️ `app/config.py` 目前**缺少** `MILVUS_HOST` / `MILVUS_PORT` / `MILVUS_DEFAULT_COLLECTION`
> 三项，不补会导致 FastAPI 完全起不来。修复方法见 `backend/README.md`。

### 智能问答依赖的外部服务

| 依赖 | 用途 | 配置项 |
| --- | --- | --- |
| Ollama | 嵌入 + LLM 生成 | `OLLAMA_BASE_URL`、`LLM_MODEL`、`EMBEDDING_MODEL` |
| Milvus | 分片检索 | `MILVUS_*`（6 项） |

> 这两点都会导致 FastAPI 起不来。修复方法见 `backend/README.md` 与 `docs/05-智能问答与语音.md`。

### 字段兼容性

| 字段 | FastAPI 写入 | Next.js 写入 | 兼容性 |
| --- | --- | --- | --- |
| `file_name` | `{base}_{8位hex}{ext}` | 同规则 | ✅ 一致 |
| `minio_path` | 预签名 URL（7 天过期） | `bucket/key` 稳定键 | ✅ 两种都能解析（`parseObjectKey`） |
| `status` | 固定 `uploaded` | 同 | ✅ |
| `chunk_strategy` | 固定 `adaptive` | 表单可选，默认 `adaptive` | ✅ |
| `version_no` | 不设置（NULL） | 1 | ✅ 读取时 `?? 0` 兜底 |

读取时对过期 URL 有兜底：不用存的 URL，而是解析出 bucket/key 后用当前凭据直连。
