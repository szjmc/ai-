## 快速开始

```bash
# 1. 配置连接（写在 .env.local，不会被平台覆盖）
cat > .env.local <<'EOF'
MINIO_ENDPOINT="127.0.0.1:9100"
MINIO_ACCESS_KEY="minioadmin"
MINIO_SECRET_KEY="minioadmin"
MINIO_SECURE=False
KB_BUCKET_NAME="knowledge-base"
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=123456
MYSQL_DB=test_db
EOF

# 2. 在目标 MySQL 库建表（已有表不要重复执行）
mysql -uroot -p123456 test_db < backend/sql/knowledge_files.sql

# 3. 启动
npm install
npm run dev     # http://localhost:3000
```

## 一句话说明关键设计

- **不改你的表结构**：`knowledge_files` 13 个字段原样使用，`file_size` / `original_name` 从 MinIO 对象元数据读取，不额外建列。
- **双模式自动切换**：MySQL 可达走 MySQL+MinIO；不可达自动降级到 `storage/ledger.json` 本地暂存，页面顶部明确提示。
- **文档原样保留**：`backend/` 下你提供的 FastAPI 代码未改动一行；上传时若该服务在线会优先转发。
- **分片功能是纯透传**：Next.js 不实现分词、向量化或 Milvus 写入，只把请求转发给 FastAPI 并展示返回结果。FastAPI 未启动时直接报错，不做本地兜底。
- **问答功能同样是纯透传**：向量检索、BM25、多路召回、重排、LLM 生成全在你的 Python 服务里；前端只采集输入（文字 / 表单 / 语音）并渲染结果。
- **前端从未实现切片**：页面上的 `adaptive/fixed/semantic/...` 只是 `knowledge_files.chunk_strategy` 字段的取值，真正的切分是后端 `JiebaChunkingStrategy`。详见 [文档 05 第 0 节](./05-智能问答与语音.md#0-先澄清一个误解前端从来没有实现切片策略)。
