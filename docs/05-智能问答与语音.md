# 05 · 智能问答与语音（NRS2002）

本轮新增四件事：**① 自然语言调用 ② 表单采集数据调用 ③ 语音转文字 ④ 结果语音播报**。

核心原则：**检索、重排、LLM 全部在你已有的 Python 后端里完成，前端只做输入采集与转发**。

---

## 0. 先澄清一个误解：前端从来没有实现切片策略

你提到"前端代码实现了好多切片策略"。我核对了源码，**前端没有任何分词或切片实现**：

```bash
$ grep -rn "chunk_size\|splitDocument\|jieba\|RecursiveCharacter" src/
src/components/chunk-dialog.tsx:174:  …分片参数与策略由后端 chunk_router.py 固定…
src/app/api/v1/chunks/parseFile/route.ts:6:  // Chunking is long-running: downloading, jieba, …
src/lib/chunk-proxy.ts:14:  // Chunking downloads from MinIO, runs jieba, …
```

三处都只是**注释和说明文字**。你在页面上看到的 `adaptive / fixed / semantic / recursive / paragraph` 是
`knowledge_files.chunk_strategy` **这个数据库字段的取值**（对应你 SQL 脚本里的列），用于记录"打算怎么切"，
真正执行切分的一直是你的 `JiebaChunkingStrategy(chunk_size=800, chunk_overlap=100)`。

所以**无需删除任何前端切片代码**——本来就没有。本轮新增的问答界面同样不碰检索逻辑。

## 2. ⚠️ 启动前必须处理的三个问题

### 2.1 `config.py` 缺 12 项配置（否则整个 FastAPI 起不来）

Python 的默认参数在**类定义时**求值，`rag_query_service.py` 与 `chunk_service.py` 都在签名里写了
`settings.XXX`，缺任意一项 → `AttributeError` → 路由导入失败 → 整个服务启动失败（连上传接口也一起挂）。

需要补充的 12 项（完整代码见 `backend/patches/config_additions.txt`，可直接粘贴）：

```python
MILVUS_HOST  MILVUS_PORT  MILVUS_URI  MILVUS_DEFAULT_COLLECTION
MILVUS_DEFAULT_ALIAS  MILVUS_DEFAULT_DB
LLM_STRATEGY  EMBEDDING_STRATEGY
SILICON_FLOW_API_KEY  SILICON_FLOW_BASE_URL
SILICON_FLOW_LLM_MODEL  SILICON_FLOW_EMBEDDING_MODEL
```

`backend/.env` 里我已经把对应环境变量都写好了。

### 2.2 `ChatBotQueryRouter.__init__` 会在启动时连接 Ollama/Milvus

```python
class ChatBotQueryRouter(BaseRouter):
    def __init__(self):
        ...
        self.chunk_service = ChunkService()   # ← 构造即连 Ollama + Milvus 并做嵌入测试
```

而 `main.py` 在模块级就构造了它。**只要 Ollama 或 Milvus 没起，FastAPI 就起不来**。
建议改成惰性初始化（补丁已写在 `config_additions.txt` 里）：

```python
self._chunk_service = None

@property
def chunk_service(self):
    if self._chunk_service is None:
        self._chunk_service = ChunkService()
    return self._chunk_service
```

### 2.3 `except` 分支里用了不存在的 `.code`，会把 400/404 变成空泛 500

```python
except (NotFoundException, ValidationException) as e:
    return ApiResponse(status=e.code, ...)      # ← AttributeError
```

`NotFoundException` / `ValidationException` 继承 `BaseAPIException(HTTPException)`，只有 `.status_code`，
没有 `.code`（`.code` 是 `RAGException` 的属性）。这一行会再抛 `AttributeError`，最终用户只看到 500。

建议改为：

```python
return ApiResponse(status=getattr(e, "status_code", 400), message=str(getattr(e, "detail", e)), data={})
```

## 3. 前端如何调用后端

一条链路，三层，没有任何一处做检索：

```
AssistantDialog（收集输入）
  → src/lib/client-api.ts : askRagQuery()
    → POST /api/v1/chat/systemRagQuery          ← Next.js 透传代理
      → {FASTAPI_URL}/api/v1/chat/systemRagQuery ← 你的 FastAPI
        → ChatBotQueryRouter.system_rag_query()
          → get_rag_service() → RAGQueryService
            → 向量检索 → PromptTemplate → LLM → 校验 JSON → 返回
```

### 3.1 代理层（`src/lib/chat-proxy.ts`）

```ts
export async function forwardRagQuery(payload: RagQueryPayload): Promise<{ message: string; data: unknown }> {
  const cfg = getBackendConfig();
  const url = `${cfg.fastapiUrl}/api/v1/chat/systemRagQuery`;
  const response = await fetch(url, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(payload),          // ← 原样转发，不加工
    signal: AbortSignal.timeout(QUERY_TIMEOUT_MS),
    cache: "no-store",
  });
  // …错误翻译（见 5.3）
}
```

`QUERY_TIMEOUT_MS = 5 * 60 * 1000`：一次问答要嵌入问题、查 Milvus、跑 LLM。

### 3.2 接口层（`src/app/api/v1/chat/systemRagQuery/route.ts`）

按后端 `UserQueryRequest` 的三个必填字段做前置校验，报错比等 500 更明确：

```ts
if (typeof body.question !== "string" || !body.question.trim()) return apiFail(400, "缺少 question（请描述患者信息）");
if (typeof body.file_id !== "string" || !body.file_id.trim()) return apiFail(400, "缺少 file_id（请先选择知识文件）");
if (typeof body.collection_name !== "string" || !body.collection_name.trim()) return apiFail(400, "缺少 collection_name（Milvus 集合名）");
```

### 3.3 请求体

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `question` | 自然语言输入框 / 表单拼装 / 语音转写 | 患者信息描述 |
| `file_id` | 下拉选择（来自 `/api/v1/file/list`） | 必须与 Milvus 里分片的 `file_id` 元数据一致 |
| `collection_name` | 手动填写，默认 `knowledge_chunks`，存 localStorage | **是 Milvus 集合名，不是知识库的 `collection_name`** |
| `top_k` | 固定 2 | 后端 `RAG_CONFIG["default_top_k"]` 同值 |

> 界面上专门标注了 `collection_name` 的语义——这是最容易填错的一项，它与 MySQL 里的 `collection_name` 完全无关。

## 3.4 关键改进：前端直接调用后端配置（前后端分离架构）

按照「前端调用后端配置」的标准前后端分离架构：
前端**不再依赖本地文件路径去猜后端的 .env**，而是直接通过接口向运行中的 FastAPI 后端获取系统配置！

### 1. 后端新增配置与 ASR 路由
- **`GET /api/v1/config/systemConfig`**（由 `app/routers/config_router.py` 提供）：
  直接向前端返回后端已加载的 ASR 语音模型名、端点、是否有 API Key、以及 Milvus 的默认集合名和策略。
- **`POST /api/v1/asr/transcribe`**（由 `app/routers/asr_router.py` 提供）：
  接收前端录制的音频文件，直接在后端使用后端的 `ASR_BASE_URL`、`ASR_MODEL`、`ASR_API_KEY` 调用语音大模型（如 Qwen3-ASR / 火山 / Qwen3-Omni），将文字返回前端。

### 2. 前端自适应解析链路
前端的 `/api/v1/chat/status` 和 `/api/v1/chat/asr` 采用智能多级探测：
1. **优先直接调用运行中的 FastAPI 后端接口**（`GET /api/v1/config/systemConfig` 和 `POST /api/v1/asr/transcribe`），配置来源标记为 `FastAPI 后端接口`。
2. 若后端接口暂时不可用（例如尚未启动），回退读取后端的 `backend/.env` 或本地环境变量。
3. 界面上提供「⚙ ASR 设置」面板，即使跨机器或需要快速测试，也可在前端界面直接填入或修正 Key，点击「从后端同步配置」一键刷新。

这样彻底解决了前端找不到后端的 .env 或跨目录运行报错的问题！

## 4. 四个任务的实现

### ① 自然语言调用

用户直接用一段话描述患者情况，前端原样发送。

```tsx
<textarea
  value={question}
  placeholder="例：患者女性，65岁，BMI 19.2，2型糖尿病稳定期，近3个月体重从65kg降至62kg（下降4.6%），无进食困难"
  onChange={(e) => setQuestion(e.target.value)}
/>
<button
  className="btn btn-primary"
  disabled={running || !question.trim()}
  onClick={() => submit(question)}
>
  {running ? "查询中…" : "提交查询"}
</button>
```

```tsx
async function submit(text: string) {
  if (!text.trim()) { setError("请先填写或说出患者信息"); return; }
  if (!fileId) { setError("请选择关联的知识文件"); return; }
  if (!collection.trim()) { setError("请填写 Milvus 集合名"); return; }
  window.localStorage.setItem("kb_milvus_collection", collection.trim());

  setRunning(true); setError(""); setResult(null); setElapsed(0);
  try {
    const data = await askRagQuery({
      question: text.trim(), file_id: fileId, collection_name: collection.trim(), top_k: 2,
    });
    setResult(data);
    onToast("ok", `查询完成：NRS2002 ${data.score_info?.score ?? "?"} 分`);
  } catch (caught) {
    setError(caught instanceof Error ? caught.message : "查询失败");
    onToast("err", caught instanceof Error ? caught.message : "查询失败");
  } finally {
    setRunning(false);
  }
}
```

### ② 表单采集数据调用

表单字段按 NRS2002 的三个维度组织，提交前**组装成一句自然语言**再发送——
这样后端拿到的是和自然语言入口完全相同的格式，不需要为表单单独写接口。

```ts
function buildQuestion(form: FormState) {
  const parts: string[] = [];
  if (form.age.trim()) parts.push(`${form.age.trim()}岁`);
  parts.push(form.inpatient === "1" ? "住院患者" : "非住院患者");
  if (form.bmi.trim()) parts.push(`BMI ${form.bmi.trim()}`);
  if (form.weightLoss.trim()) parts.push(`近3个月体重下降 ${form.weightLoss.trim()}%`);
  if (form.intakeLoss.trim()) parts.push(`近1周进食量减少 ${form.intakeLoss.trim()}%`);
  if (form.disease.trim()) parts.push(form.disease.trim());
  if (form.note.trim()) parts.push(form.note.trim());
  return `${parts.join("，")}。请根据 NRS2002 规则给出评分与依据。`;
}
```

字段与维度对应：

| 表单字段 | 对应 NRS2002 维度 | 预置选项 |
| --- | --- | --- |
| 年龄 | 年龄（≥70 岁得 1 分） | — |
| BMI | 营养状态受损 | — |
| 近3月体重下降% | 营养状态受损 | — |
| 近1周进食减少% | 营养状态受损 | — |
| 疾病状态 | 疾病严重程度 | 良性疾病 / 慢病急性发作 / 大手术·中风·ICU / 大面积烧伤·多器官衰竭 / 2型糖尿病稳定期 / 胃癌术后化疗 |
| 是否住院 | 影响疾病严重度判定 | 住院 / 非住院 |
| 补充说明 | 自由文本 | — |

界面上实时显示"将发送的问题"，用户在提交前能看到最终文案：

```tsx
<div className="assistant-composed">
  <span>将发送的问题</span>
  <p>{buildQuestion(form)}</p>
</div>
```

### ③ 语音转文字

浏览器录音 → 上传到 Next.js 代理 → 转发到**兼容 OpenAI `/audio/transcriptions`** 的服务 →
把文字填进输入框。**识别本身不在本项目内实现**，只做转发，因此可以自由换成
Qwen3-ASR / 火山 / Qwen3-Omni，只要该服务提供 OpenAI 兼容接口。

#### 配置读取顺序

语音代理跑在 **Next.js 服务端**，它只能看到本应用的环境变量。为了让你已有的后端配置直接生效，
解析顺序是：

1. 本应用环境变量（`.env.local` 等，`process.env.ASR_*`）
2. **服务端读取 `backend/.env`**（与 Python 后端共用同一份配置，优先级更低但免复制粘贴）

所以把 `ASR_*` 写在 `backend/.env` 里即可，无需在 `.env.local` 再抄一份。
部署到另一台机器、`backend/.env` 不在一起时，才需要在 `.env.local` 里单独配置。

```dotenv
# backend/.env 或 .env.local 均可
ASR_BASE_URL="https://api.siliconflow.cn/v1/audio/transcriptions"
ASR_MODEL="Qwen/Qwen3-ASR-1.7B"
ASR_API_KEY="sk-xxxx"
```

> **`ASR_BASE_URL` 写成 base 或完整端点都支持**：
> `https://host/v1` 与 `https://host/v1/audio/transcriptions` 等价，代码会归一化，
> 不会拼成 `.../audio/transcriptions/audio/transcriptions`。

改完配置后点界面左侧「重新检测服务」即可生效（服务端有 10 秒缓存）。

#### 接口返回的 ASR 状态

`GET /api/v1/chat/status` 的 `asr` 字段会告诉你配置是否被读到、以及来源：

```json
{ "configured": true, "model": "Qwen/Qwen3-ASR-1.7B",
  "endpoint": "https://api.siliconflow.cn/v1/audio/transcriptions",
  "has_api_key": true, "source": "backend/.env" }
```

`source` 可为 `env` / `backend/.env` / `none`。界面上也会显示「识别模型 / 配置来源 / 鉴权」，
一眼能看出是没读到配置，还是读到了但密钥不对。

#### 常见报错对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 界面提示「语音识别未配置」 | 两处都没读到 `ASR_BASE_URL` / `ASR_MODEL` | 检查 `backend/.env` 或 `.env.local`，然后点「重新检测服务」 |
| `鉴权失败（HTTP 401）` | **API Key 无效** | 去服务商控制台重新复制完整 key。可用 `curl -H "Authorization: Bearer $KEY" https://api.siliconflow.cn/v1/models` 自测，返回 `Token is invalid` 就是 key 的问题 |
| `接口不存在（HTTP 404）` | 端点或模型名错 | 报错信息里会回显实际请求的 endpoint 与 model |
| `未返回文字`（422） | 录音太短/太安静 | 靠近麦克风、说完整一句话（≥1 秒） |

录音（MediaRecorder，仅采集音频，不做识别）：

```tsx
function startRecording() {
  navigator.mediaDevices.getUserMedia({ audio: true }).then((stream) => {
    const recorder = new MediaRecorder(stream);
    chunksRef.current = [];
    recorder.ondataavailable = (event) => { if (event.data.size) chunksRef.current.push(event.data); };
    recorder.onstop = async () => {
      stream.getTracks().forEach((track) => track.stop());
      const blob = new Blob(chunksRef.current, { type: recorder.mimeType || "audio/webm" });
      setTranscribing(true);
      try {
        const text = await transcribeAudio(blob);          // → POST /api/v1/chat/asr
        setQuestion((current) => (current ? `${current}${text}` : text));
      } catch (caught) {
        setError(caught instanceof Error ? caught.message : "语音识别失败");
      } finally { setTranscribing(false); }
    };
    recorder.start();
    recorderRef.current = recorder;
    setRecording(true);
  }).catch(() => setError("无法访问麦克风，请检查浏览器权限。"));
}
```

代理层（`src/lib/chat-proxy.ts`）：

未配置时界面会**明确提示需要哪些环境变量并禁用录音按钮**，不会让用户点了没反应。

转写完成后文字进入可编辑的输入框，用户可以先改错别字再提交——语音识别难免有误，这一步很重要。

### ④ 结果语音播报

用浏览器内置 `speechSynthesis`（Web Speech API），无需额外依赖或密钥。
播报内容把结构化评分转成一句人话：

```ts
function resultToSpeech(result: RagQueryResult) {
  const info = result.score_info;
  const risk = info.score >= 3 ? "存在营养风险，建议启动营养支持" : "暂未达到营养风险，建议继续监测";
  return `NRS2002 评分为 ${info.score} 分，${risk}。其中营养状态受损 ${info.nutritional_impairment} 分，`
       + `疾病严重程度 ${info.disease_severity} 分，年龄 ${info.age} 分。评分依据：${info.basis}`;
}

function speak(text: string, onDone: () => void) {
  if (!("speechSynthesis" in window)) return false;
  window.speechSynthesis.cancel();
  const utterance = new SpeechSynthesisUtterance(text);
  utterance.lang = "zh-CN";
  utterance.onend = onDone;
  utterance.onerror = onDone;
  window.speechSynthesis.speak(utterance);
  return true;
}
```

按钮支持"播报 / 停止"切换，关闭窗口时会 `speechSynthesis.cancel()` 避免继续发声。

## 5. 结果如何呈现

后端返回结构（`chatbot_query_router.py` 的 `response_data`）：

```
score_info      → 大号总分 + 三个维度 + 评分依据
source_basis[]  → 命中的规则片段（用于人工核验 LLM 有没有乱编）
query_params    → 本次查询参数与时间
```

界面对应三块：

```tsx
<div className="assistant-score">
  <div><span>NRS2002 总分</span><strong>{result.score_info.score}</strong>
       <em>{result.score_info.score >= 3 ? "存在营养风险" : "暂未达风险阈值"}</em></div>
  <dl>
    <div><dt>营养状态受损</dt><dd>{result.score_info.nutritional_impairment}</dd></div>
    <div><dt>疾病严重程度</dt><dd>{result.score_info.disease_severity}</dd></div>
    <div><dt>年龄</dt><dd>{result.score_info.age}</dd></div>
  </dl>
</div>
<div className="assistant-basis"><span>评分依据（后端 LLM 生成）</span><p>{result.score_info.basis}</p></div>
<ul>{result.source_basis.map(…)}</ul>   {/* 每条显示 file_name / retrieval_type / rule_fragment */}
```

`source_basis` 刻意保留：LLM 评分是否可信，靠它对照原始规则片段来核验。

### 5.1 错误如何翻译

| 情况 | 返回 | 提示 |
| --- | --- | --- |
| FastAPI 未启动 | 503 | `无法连接查询服务 … 请确认 FastAPI 已启动（backend/ 目录执行 python main.py）` |
| 上游 500 | 502 | `查询服务返回 500：… 常见原因是 Milvus 无数据、Ollama 模型未拉取或 LLM 输出不是合法 JSON，详细原因请查看 FastAPI 控制台日志` |
| 200 但 `data` 为空 | 502 | `查询服务未返回结果数据…` |
| 后端 404 | 404 | 原样透传，如 `指定file_id=xxx无匹配的NRS2002规则数据` |
| 超过 5 分钟 | 504 | `查询超时…请查看 FastAPI 日志` |
| 缺必填字段 | 400 | 代理层前置校验 |

## 6. 已知限制（都是后端现有行为，未改动）

1. **`retrieval_type` 未透传**。`UserQueryRequest` 没有该字段，路由调用 `query_score()` 时也没传，
   所以**当前所有请求都走默认的 `vector` 单路检索**。
   你的 `multi_retrieval_rerank`（多路召回 + 重排）目前只能通过 `rag_query_rerank_service.py` 的
   `__main__` 测试入口跑，**HTTP 上无法触发**。
   若要开放，需要：路由改用 `from app.services.rag_query_rerank_service import RAGQueryService`，
   并给 `UserQueryRequest` 加 `retrieval_type: Literal["vector","bm25","hybrid","multi_rerank"] = "vector"` 再传给 `query_score()`。
   前端届时只需多一个下拉框（`top_k` 已是现成范例）。
2. **Milvus 集合名要自己对上**。分片写入的是 `MILVUS_DEFAULT_COLLECTION`（默认 `knowledge_chunks`），
   问答要查同一个集合名，否则报"无匹配数据"。
3. **`file_id` 必须真在 Milvus 里**。分片时写入的元数据 `file_id` 才有效；仅上传未分片的文件查不到。
4. **一次问答会重新初始化 RAG 服务**。`get_rag_service()` 每次请求都 `new RAGQueryService(...)`，
   会重新做嵌入测试与连接，比较慢（秒级到十几秒）。如果要提速，可给它加 `@lru_cache`。

## 7. 一次真实排查记录（2026-10）

配置写进 `backend/.env` 后界面仍显示"语音识别未配置"。逐层核对结果：

| 检查项 | 结果 |
| --- | --- |
| Next.js 能否看到 `ASR_*` | ❌ 不能——代理跑在 Next 服务端，只读自己的环境变量 |
| 拼接后的请求地址 | ❌ `.../v1/audio/transcriptions/audio/transcriptions`（配置已含完整路径，代码又拼了一次） |
| 修复后配置是否读到 | ✅ `source: backend/.env`，`configured: true` |
| 端点是否正确 | ✅ `https://api.siliconflow.cn/v1/audio/transcriptions` |
| 真实调用 SiliconFlow | ❌ **HTTP 401** |
| 交叉验证 `GET /v1/models` | ❌ `{"code":30014,"message":"Token is invalid."}` |

**结论**：前两个问题已修复（配置回退读取 + 端点归一化）；当前卡点是 **API Key 无效**。
给出的 key 只有 20 个字符（`sk-` + 17 位），而 SiliconFlow 的 key 通常更长，复制时应被截断了。
需要到控制台重新复制完整 key，替换 `ASR_API_KEY` 后点「重新检测服务」。

排查过程中顺带做了两处改进：

- 界面显示 ASR 的「识别模型 / 配置来源 / 鉴权状态」，避免再出现"到底读没读到配置"的疑问；
- 默认 Milvus 集合名改为从后端 `MILVUS_DEFAULT_COLLECTION` 读取（当前为 `rag_knowledge`），
  避免前端默认值与后端写入的集合不一致导致"无匹配数据"。
