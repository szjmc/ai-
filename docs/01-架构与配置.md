# 01 · 架构与配置

## 1. 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端框架 | Next.js 16（App Router） | React 19，服务端路由处理器承担后端职责 |
| 样式 | 原生 CSS（`src/app/globals.css`） | 不依赖外部字体与图片，避免 CDN 404 |
| 数据库 | MySQL（`mysql2` + `drizzle-orm`） | 只用 `drizzle-orm` 的 `sql` 模板做参数绑定，不做迁移 |
| 对象存储 | MinIO（官方 `minio` SDK） | 原文件读写 |
| DOCX 解析 | `mammoth` + `sanitize-html` | 转为经白名单清洗的 HTML |
| XLSX 解析 | `xlsx`（SheetJS） | 保留真实行列号、合并单元格 |
| 测试 | `node:test` + `@playwright/test` | 24 项单元测试 + 4 套浏览器回归 |

## 3. 整体数据流

```
浏览器组件
   │  调用 src/lib/client-api.ts 的函数（唯一出口）
   ▼
fetch / XMLHttpRequest
   │
   ▼
src/app/api/**/route.ts        ← 解析参数、校验、统一响应包装
   │  调用
   ▼
src/lib/knowledge.ts           ← ★ 业务总入口
   │  先 resolveStorage() 探测 MySQL 是否可达
   ├── 可达 ──► mysqlXxx()    ──► MySQL (knowledge_files) + MinIO
   └── 不可达 ► localXxx()    ──► storage/ledger.json + storage/buckets/
```

**关键点**：所有前端请求都经过 `client-api.ts`，组件内不出现裸 `fetch`；所有后端业务都经过 `knowledge.ts`，接口层不直接碰数据库。

## 4. 双模式存储

`src/lib/storage-mode.ts` 负责探测，结果缓存 8 秒：

```ts
const TTL = 8000;
let cached: Cached | null = null;
let inflight: Promise<ProbeResult> | null = null;

async function probe(): Promise<ProbeResult> {
  const minioPromise = probeMinio();           // 并行探测 MinIO
  try {
    await ensureMysqlSchema();                 // SELECT ... LIMIT 0 验证表存在
    return { ok: true, mode: "mysql", minioReachable: await minioPromise };
  } catch (error) {
    const { reason, hint } = describeDbError(error);
    return { ok: false, mode: "local", minioReachable: await minioPromise, reason, hint };
  }
}

export async function resolveStorage(force = false): Promise<ProbeResult> {
  if (!force && cached && Date.now() - cached.at < TTL) return cached.result;
  if (!inflight) inflight = probe().finally(() => { inflight = null; });
  const result = await inflight;
  cached = { at: Date.now(), result };
  return result;
}
```

表校验故意只做只读验证，**绝不自动建表或改表**：

```ts
// src/lib/mysql-minio.ts
export async function ensureMysqlSchema() {
  await db.execute(sql`SELECT id, file_name, minio_path FROM knowledge_files LIMIT 0`);
}
```

错误被翻译成可执行的中文提示（`describeDbError`）：

| 底层错误 | reason | hint |
| --- | --- | --- |
| `ECONNREFUSED` | 未检测到本机 MySQL（127.0.0.1:3306） | 启动 MySQL 与 MinIO 后自动切换为直连模式 |
| `ER_ACCESS_DENIED_ERROR` | MySQL 账号或密码认证失败 | 检查 .env 中的 MYSQL_USER 与 MYSQL_PASSWORD |
| `ER_BAD_DB_ERROR` | MySQL 数据库 test_db 不存在 | 先执行 CREATE DATABASE test_db CHARACTER SET utf8mb4; |
| `ER_NO_SUCH_TABLE` | knowledge_files 表不存在 | 执行 backend/sql/knowledge_files.sql |

`knowledge.ts` 中每个导出函数都按探测结果分发：

```ts
export async function listKnowledgeFiles(query: ListQuery = {}) {
  const probe = await resolveStorage();
  return probe.ok ? mysqlList(query, probe.minioReachable) : localList(query);
}
export async function saveUploadedFile(input: UploadInput) {
  const probe = await resolveStorage();
  return probe.ok ? mysqlSave(input) : localSave(input);
}
export async function updateKnowledgeFileContent(id: string, input: UpdateContentInput) {
  const probe = await resolveStorage();
  return probe.ok ? mysqlUpdateContent(id, input, probe.minioReachable) : localUpdateContent(id, input);
}
```

> **本地模式不是 MySQL 的副本**，不会自动同步。页面顶部会显示明确提示，`storage_mode` 字段也会返回 `"local"`。

## 5. 环境变量

读取集中在 `src/lib/backend-config.ts`，**凭据只在服务端使用，永不返回给浏览器**：

```ts
function env(name: string, fallback = "") {
  return (process.env[name] ?? fallback).trim().replace(/^["']|["']$/g, "");  // 去掉 .env 里的引号
}

export function getBackendConfig() {
  const endpoint = env("MINIO_ENDPOINT", "127.0.0.1:9100");
  const minioSecure = env("MINIO_SECURE", "False").toLowerCase() === "true";
  const url = new URL(/^https?:\/\//i.test(endpoint) ? endpoint : `${minioSecure ? "https" : "http"}://${endpoint}`);
  return {
    minioEndpoint: url.host,
    minioHost: url.hostname,
    minioPort: Number(url.port || (minioSecure ? 443 : 80)),
    minioSecure,
    minioAccessKey: env("MINIO_ACCESS_KEY", "minioadmin"),
    minioSecretKey: env("MINIO_SECRET_KEY", "minioadmin"),
    minioBucket: env("MINIO_BUCKET", "vanna-training-data"),
    kbBucketName: env("KB_BUCKET_NAME", DEFAULT_BUCKET),
    mysqlHost: env("MYSQL_HOST", "127.0.0.1"),
    mysqlPort: Number(env("MYSQL_PORT", "3306")),
    mysqlUser: env("MYSQL_USER", "root"),
    mysqlPassword: env("MYSQL_PASSWORD", "123456"),
    mysqlDb: env("MYSQL_DB", "test_db"),
    fastapiUrl: env("FASTAPI_URL", "http://127.0.0.1:8018").replace(/\/$/, ""),
  };
}
```

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `MINIO_ENDPOINT` | `127.0.0.1:9100` | MinIO 地址，支持带 `http://` 前缀 |
| `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | `minioadmin` | MinIO 凭据 |
| `MINIO_SECURE` | `False` | 是否 HTTPS |
| `KB_BUCKET_NAME` | `knowledge-base` | 知识文件桶 |
| `MYSQL_HOST` / `PORT` / `USER` / `PASSWORD` / `DB` | `127.0.0.1` / `3306` / `root` / `123456` / `test_db` | MySQL 连接 |
| `FASTAPI_URL` | `http://127.0.0.1:8018` | 可选，FastAPI 在线时优先转发上传 |
| `KB_OPERATORS_FILE` | `storage/operators.json` | 可选，操作人名单位置 |
| `KB_STORAGE_ROOT` | `storage/` | 可选，本地暂存根目录（降级模式的 `ledger.json` 与 `buckets/`），测试与容器挂载时可重定向 |

> `KB_STORAGE_ROOT` 与 `KB_OPERATORS_FILE` 都是**惰性读取**（调用时才解析），所以进程内改环境变量也能生效：
> ```ts
> // src/lib/local-ledger.ts
> function storageRoot() {
>   return process.env.KB_STORAGE_ROOT || path.join(process.cwd(), "storage");
> }
> function ledgerFile() { return path.join(storageRoot(), "ledger.json"); }
> ```

> **写在 `.env.local`**：托管平台每次构建会重写根目录 `.env`，`.env.local` 优先级更高且不会被覆盖。

MySQL 连接池懒加载，避免模块导入期就抛错：

```ts
// src/db/index.ts
export const db = new Proxy({} as MySql2Database, {
  get(_target, key) {
    const database = getDatabase();   // 首次访问时才建池
    const value = Reflect.get(database, key);
    return typeof value === "function" ? value.bind(database) : value;
  },
});
```

### 6.3 三个"表里没有"的字段怎么来的

| 字段 | 来源 | 代码位置 |
| --- | --- | --- |
| `file_size` | MinIO `statObject().size`，带 60 秒缓存 | `mysql-minio.ts` → `getObjectMetadata()` |
| `original_name` | 优先读 MinIO 自定义元数据 `X-Amz-Meta-Original-Name`；没有就从存储名反推 | `records.ts` → `deriveOriginalName()` |
| `content_type` | 由 `file_type` 查 `CONTENT_TYPES` 映射表 | `records.ts` → `deriveContentType()` |

反推逻辑（去掉后端生成的 8 位十六进制后缀）：

```ts
// src/lib/file-search.ts
export function originalFileName(stored: string) {
  const leaf = stored.split(/[\\/]/).pop() || stored;
  return leaf.replace(/_([0-9a-f]{8}|seed\d+)(\.[^.]+)$/i, "$2");
}
// 营养筛查-BMI_f3fa4a9b.xlsx → 营养筛查-BMI.xlsx
```

### 6.4 统一响应格式（`src/lib/http.ts`）

与你原有 FastAPI 的 `ApiResponse` 结构一致：

```ts
export function apiOk(message: string, data: unknown = null, page: unknown = null, http = 200) {
  return Response.json({ status: 200, message, data, page }, { status: http, headers: { "Cache-Control": "no-store" } });
}
export function apiFail(statusCode: number, message: string, data: unknown = null) {
  return Response.json({ status: statusCode, message, data, page: null }, { status: statusCode, headers: { "Cache-Control": "no-store" } });
}
export function fromError(error: unknown) {
  if (error instanceof ApiError) return apiFail(error.statusCode, error.message);
  console.error("Knowledge file operation failed:", error);
  if (isDbError(error)) {
    const { reason, hint } = describeDbError(error);
    return apiFail(503, reason, { hint });
  }
  // 绝不把 SQL、堆栈或凭据暴露给浏览器
  return apiFail(500, "文件处理失败，请稍后重试或联系管理员检查服务日志");
}
```
